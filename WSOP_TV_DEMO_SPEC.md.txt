당신은 시니어 프론트엔드 개발자이자 UX 엔지니어입니다.

WSOP 포커 토너먼트를 시청하는 ‘WSOP TV’의 실제 동작하는 반응형 데모 웹사이트를 구현해 주세요. 설명이나 정적 목업만 제공하지 말고, 사용자가 화면을 이동하고 방송·영상을 선택할 수 있는 코드를 작성하고 실행해 주세요.

## 1. 목적과 구현 범위

- PC와 모바일 브라우저에서 공통 사용자 경험을 검증한다.
- React + TypeScript를 기본으로 사용한다. 기존 프로젝트가 있다면 기존 기술 구성을 우선한다.
- 실제 AWS, GGPass, EBS, 결제 시스템에는 연결하지 않는다.
- 로그인·구독·경기 데이터는 Mock 데이터와 로컬 상태로 구현한다.
- 실제 서비스로 오해하지 않도록 ‘Demo’ 표시를 제공한다.
- 공개 배포나 외부 시스템 변경은 하지 않는다.

## 2. 서비스의 핵심 경험

일반적인 영상 목록 중심 OTT가 아니라 ‘지금 진행 중인 토너먼트 시청’을 중심으로 설계한다.

핵심 흐름:
토너먼트 시청 → 핸드 리플레이 → 플레이어 프로필 → 과거 결승 → 해당 대회 다시보기

보조 흐름:
토너먼트 시청 ↔ 스케줄
무료 하이라이트 → 로그인·구독 안내 → 원래 콘텐츠 복귀

Tournament Ticker는 화면 상단에서 대회와 방송을 선택하는 리모컨 역할을 한다.

## 3. 필수 화면

### A. 토너먼트 시청
- 가장 중요한 기본 화면이다.
- 상단에 Tournament Ticker를 배치한다.
- 현재 선택된 대회·방송을 명확히 표시한다.
- 영상 플레이어를 중심으로 대회명, 시즌, Day, 테이블, 방송 상태를 표시한다.
- 여러 방송이 있는 대회에서는 카드를 선택해 하나의 방송을 재생한다.
- 화면분할 동시 시청은 구현하지 않는다.
- 영상 아래에 Overview / Players / Hand History 탭을 제공한다.
- Players에는 선수명·칩 카운트·순위를 표시한다.
- Hand History에는 샘플 핸드 기록과 리플레이 링크를 표시한다.
- 경기 정보는 실제 EBS 연동이 아닌 샘플 데이터임을 표시한다.
- 관련 핸드 리플레이를 선택하면 해당 영상 상세로 이동한다.

### B. 핸드 리플레이
- 핵심 핸드 클립 목록과 상세 재생 화면을 제공한다.
- 관련 대회, 핸드 설명, 등장 플레이어를 표시한다.
- 플레이어 이름을 누르면 프로필로 이동한다.
- ‘원래 방송으로 돌아가기’를 제공한다.

### C. 플레이어 프로필
- 이름, 프로필 이미지 또는 대체 이미지, 소개, 샘플 성적을 표시한다.
- 관련 핸드 영상과 PAST FINALS 목록을 제공한다.
- 과거 결승 선택 시 해당 시즌 대회의 다시보기 화면으로 이동한다.
- 과거 대회 화면은 라이브 화면과 같은 틀을 사용하되 ‘Replay’ 상태를 명확히 표시한다.

### D. 스케줄
- 날짜별 예정·진행 중·종료 대회를 표시한다.
- 시간대와 방송 시작 시간을 명확히 표시한다.
- Watch 버튼은 해당 대회의 시청 화면으로 연결한다.
- 방송이 없거나 일정이 없는 상태도 구현한다.

### E. 랜딩
- 서비스 소개와 무료 하이라이트를 먼저 보여준다.
- 구독 안내 CTA를 제공한다.
- 가격은 확정 가격으로 표현하지 않고 ‘Demo plan’으로 표시한다.

### F. 아카이브
- 시즌·이벤트 필터로 과거 영상을 탐색한다.
- 영상 선택 시 다시보기 화면으로 이동한다.
- 재생 권한이 없으면 로그인 또는 구독 안내를 제공한다.

## 4. 데모용 로그인·권한

다음 정책은 데모 가정이며 추후 교체할 수 있게 별도 설정으로 관리한다.

- Guest: 하이라이트 재생, 스케줄·아카이브 목록·프로필 탐색
- Free: Guest 권한 + 지정된 무료 VOD
- Standard: Free 권한 + 메인 라이브·유료 VOD
- Platinum: Standard 권한 + 추가 테이블 방송 선택

데모 도구에서 상태를 전환할 수 있게 한다.
실제 이메일·비밀번호나 결제 정보는 수집하지 않는다.

- 비로그인 사용자가 제한 콘텐츠를 선택하면 로그인 안내를 보여준다.
- 로그인 후 권한이 부족하면 구독 안내를 보여준다.
- 데모 로그인·플랜 변경 후 원래 선택한 콘텐츠로 복귀한다.
- 모달을 닫으면 탐색은 계속 가능하지만 제한 콘텐츠는 재생하지 않는다.
- 탐색 중 홍보 모달과 재생 권한 안내를 구분한다.
- 사용자 상태와 이어보기 기록은 localStorage에 저장한다.

## 5. 반응형 디자인

전체 스타일:
- 어두운 배경, 높은 대비, 절제된 레드 포인트
- 영상과 대회 정보가 중심인 스포츠 중계 화면
- 큰 배너·장식보다 정보의 가독성과 조작 편의성을 우선
- UI 언어는 영어를 기본으로 한다.
- 공식 이미지 사용 권한이 없으면 대체 이미지를 사용한다.

PC:
- 넓은 플레이어와 관련 정보를 효율적으로 배치한다.
- Ticker는 가로형 카드로 구성한다.
- 보조 정보는 사이드 또는 하단에 배치한다.

모바일:
- 플레이어를 상단에 배치한다.
- Ticker는 가로 스크롤을 지원한다.
- 탭·통계·관련 영상은 세로로 배치한다.
- 긴 이름과 큰 칩 숫자가 레이아웃을 깨뜨리지 않게 한다.
- 터치 영역은 최소 44px로 확보한다.
- 전체 페이지에 의도하지 않은 가로 스크롤이 생기지 않게 한다.
- 마우스 hover 없이 모든 기능을 사용할 수 있게 한다.

## 6. 영상 재생

- 사용 가능한 샘플 영상을 HTML5 video로 실제 재생한다.
- 샘플은 실제 WSOP 중계가 아님을 표시한다.
- 여러 방송 카드는 각각 다른 방송 정보와 선택 상태를 갖는다.
- 샘플 소스가 같다면 이를 명확히 표시한다.
- 라이브는 샘플 영상 기반 시뮬레이션으로 구현하고 실제 라이브·DVR 제공으로 표현하지 않는다.
- 브라우저가 자동재생을 차단하면 재생 버튼을 제공한다.
- 재생·일시정지·음량·전체화면을 지원한다.
- 화질·자막 등 실제로 지원하지 않는 기능을 작동하는 것처럼 표시하지 않는다.
- 재생 실패 시 오류 안내와 재시도 버튼을 제공한다.

## 7. 데이터와 코드 구조

다음 데이터를 고유 ID로 연결한다.
- 시즌
- 이벤트
- 방송 세션·테이블
- 플레이어
- 핸드 클립
- 아카이브 영상

선수 이름을 텍스트로만 연결하지 않는다.
Mock 데이터를 별도 파일로 분리하고, 추후 API로 교체할 수 있는 데이터 접근 계층을 둔다.

최소 데이터:
- 진행 중 대회 2개
- 복수 방송이 있는 대회 1개
- 예정 대회 3개
- 과거 시즌 2개
- 플레이어 6명
- 핸드 리플레이 8개

모든 상세 화면은 URL로 직접 접근할 수 있어야 하며, 새로고침·뒤로가기·앞으로가기가 정상 동작해야 한다.

## 8. 예외 상태

다음을 구현한다.
- 라이브 없음
- 방송 지연·중단·종료
- 관련 핸드 없음
- 플레이어의 과거 결승 없음
- 재생 권한 없음
- 샘플 영상 재생 실패
- 존재하지 않는 콘텐츠 URL

콘텐츠가 없어도 다른 대회나 영상으로 이동할 수 있는 경로를 제공한다.

## 9. 검증과 완료 기준

다음 화면 크기를 확인한다.
- PC: 1440 × 900
- 태블릿: 768 × 1024
- 모바일: 390 × 844, 360 × 800

검증할 흐름:
1. 기본 방송 시청 → 추가 테이블 선택
2. 핸드 리플레이 → 플레이어 → 과거 결승 재생
3. 스케줄 → 해당 방송 시청
4. 제한 콘텐츠 선택 → 데모 로그인·플랜 변경 → 원래 콘텐츠 복귀
5. 다시보기 중 이탈 → 복귀 후 이어보기
6. 새로고침과 브라우저 뒤로가기

주요 링크와 버튼에 실제 동작을 연결하고, 콘솔 오류와 깨진 레이아웃을 수정한다. 실행 환경에서 확인할 수 없는 항목은 미검증이라고 명시한다.

## 10. 작업 방식과 결과 보고

- 일반적인 구현 선택은 합리적으로 판단하고, 가정은 기록한다.
- 핵심 시청 흐름을 먼저 완성한 후 보조 화면과 반응형을 마무리한다.
- README에 실행 방법, 데모 가정, 미구현 기능, 실제 API 연동 지점을 작성한다.
- 완료 시 실행 방법 또는 미리보기 주소, 검증 결과, 남은 제한 사항을 알려준다.
